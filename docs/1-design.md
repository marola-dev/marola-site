# Design

## Files

- `site/static/`: `index.html` (the map), `about.html`, `support.html` (behind "apoie"/Donate),
  `news.html` (the posts, newest first, one `article[lang]` per language each, generated from
  `site/content/news/`), `members.html` (who builds marola, generated from marola-dev/.github's
  `MEMBERS.md`),
  `404.html` (forwards old `marola.dev/docs/*` links to `docs.marola.dev`, `noindex`),
  `robots.txt`, `humans.txt` (generated from `MEMBERS.md`; `llms.txt`, `sitemap.xml` and
  `.well-known/security.txt` are written at build time, [development](3-development.md#crawl-files-and-metadata)),
  `favicon.svg`, and
  `img/umbrella{,.pt-BR}.svg`, the umbrella README's repo diagram that `about.html` shows (copied
  from marola-dev/marola `docs/img/`; recopy it when that one changes).
- `site/static/app.js`: fetches `data/areas.json` and each area's board, builds the map (Mapbox GL
  JS), the beach markers, the list, the card, the hour slider and the satellite/NASA GIBS raster
  layers. `ui.js`: language resolution and `t()` (MIP-0054), and the emergency numbers panel's open and close (#76). `flow.js`: the WebGL wind/wave
  particle layer, a Mapbox GL custom layer interpolated from the board's own readings (no weather
  grid fetched). `i18n.js`: generated by `scripts/i18n_bundle.py` from `site/i18n/*.json` — edit
  the catalogs, never this file.
- `site/static/mapbox-config.js`: empty in the repo (`window.MAROLA_MAPBOX = { token: "", style: ""
  }`); the deploy on piabrota2 rewrites it from `MAPBOX_PUBLIC_TOKEN`/`MAPBOX_STYLE`
  (`scripts/mapbox_config.sh`). `site/static/chatbot-config.js` and `chat.js`: the chat widget
  ([the chat widget](1-design_chat-widget.md)).
- `site/static/vendor/`: vendored third-party assets, no build step ([libraries](2-libraries.md)).
- `site/areas.json`: the areas the boards are built for ([reference](4-reference.md)).
  `site/fixtures/`: the board the test harness (`scripts/site_check.js`) renders, plus a schema
  fixture. `site/board.schema.json`: the board contract, vendored from the pinned image
  ([reference](4-reference.md)).
- `site/i18n/`: `pt-BR.json` (source locale), `en.json` (translated), `context.json` (a note per
  key); `scripts/i18n_bundle.py` checks and bundles them ([development](3-development.md)).
- `site/content/news/`: the news posts, one Markdown file per post and language
  ([format](../site/content/news/README.md)); `scripts/news_build.py` writes them into `news.html`.
- `site/members.version`: the marola-dev/.github commit whose `MEMBERS.md`, the org's one list of
  members (the Zenodo record's creators), `scripts/members_build.py` (`just members`) writes into
  `members.html`, copying each member's GitHub avatar into `site/static/img/members/` (the page
  hotlinks nothing). `members.yml` moves the pin to `.github`'s main and rebuilds both every day,
  as a PR for a person to merge, so a new member or photo needs no change here by hand. CI's
  `--check` fails when the page or the avatar files differ from the pinned list.

## The board, beach by beach, and markers

`app.js`'s `colour()`/`band()` turn each beach's score into one of five bands: no data (`score`
null/undefined), unfit (`unfit` or `score <= 0`), 1–39, 40–69, or ≥70 — the same bands the hour
bar's legend shows. A map marker is a 16 px SVG dot (`waveIcon`) with a white ring, the band's
colour ([`DESIGN.md`](../DESIGN.md)'s `--c70`…`--cna` tokens) written straight into its `fill`
attribute; the selected beach grows to 32 px and shows its score. Everywhere else the band is a
CSS class, never inline `style=` (which the CSP below blocks): list/card score chips use
`.c70`/`.c40`/`.c1`/`.c0`/`.cna`; the `water` layer's sampling-point markers are a droplet
(`waterDrop`), not a dot, so they never pass for a beach, filled through
`wpoint c0`/`wpoint cna`/`wpoint c70`; a beach's tooltip and its card's inline water-status dot use
`wdot c0`/`wdot cna`/`wdot c70` (`waterDotClass`). The `water` layer draws every sampling point in
the area, in the same three bands (proper, improper, unclassified).

## CSP and the no-third-party rule

`index.html`'s page keeps `default-src 'self'; img-src 'self' data: blob: https:; connect-src
'self' https:; worker-src 'self'; object-src 'none'` (`about.html`/`support.html`/`news.html`, which carry no
map, drop `connect-src`/`worker-src`: `default-src 'self'; img-src 'self' https:; object-src
'none'`). `script-src` has no override, so it inherits `default-src 'self'`: every script is
same-origin, including Mapbox GL JS's own worker (`vendor/mapbox-gl-csp.js` is the CSP build,
`vendor/mapbox-gl-csp-worker.js` loads from `vendor/`, not a `blob:`, which the non-CSP build
needs).

The page's only two third-party origins ([`AGENTS.md`](../AGENTS.md)'s Code style section) are:

- **Mapbox**: the base map (style, tiles, fonts), billed per map load above its free tier once a
  token is set (`mapbox-config.js`, [the tile policy](4-reference.md#tile-policy)).
- **NASA GIBS**: the four satellite raster layers (clouds, sea-surface temperature, anomaly,
  El Niño), free and keyless, fetched only once a visitor picks one of those layers
  (`app.js`'s `renderRaster`).

`img-src … https:` and `blob:` are how Mapbox GL decodes map imagery; `connect-src … https:` lets
the page reach Mapbox's tile/style/event endpoints and, when set, the chat widget's own endpoint
(`chatbot-config.js`). No other third-party script, font or analytics origin is loaded — Inter is
self-hosted (`vendor/fonts/`), not pulled from a font CDN.

## The Elm map page (`front/`)

The new map page is Elm, bundled by Vite ([ADR 0005](adr/0005-elm-and-haskell.md)). It replaces
`site/static/` in a later step. Until then both exist and `site/static/` is the live page. Elm owns
the model, `update` and the views; every effect goes out through a port to `front/ports.js`.

| Path | What it holds |
|---|---|
| `front/src/` | The domain types, the board decoder, the model, the messages, `update` (which returns effects as data) and the views. Pure Elm |
| `front/ports.js` | Starts the page and carries out each effect `Main.elm` sends: fetch, MapLibre, the flow layer, history, storage, audio, focus |
| `front/js/` | The other hand-written JavaScript. `maplibre_ffi.mjs` holds the MapLibre calls, `flow_layer_ffi.mjs` the WebGL wind and wave layer |
| `front/public/` | `style.css`, `favicon.png`, `og.png`, `vendor/` and `data/trails/`, copied as they are |
| `front/index.html` | The page's head, its CSP `<meta>` and the module script |
| `front/tests/` | elm-test suites, and `golden.json`, what the old page's functions return |

`scripts/front_build.sh` builds `front/dist/`; `scripts/site_build.sh` puts it into `dist/` with the
static pages. The [build section of the development guide](3-development.md#build-and-serve-the-client)
has the steps.

### The board, beach by beach, and markers

The mapping is the same as the old page's. `Band.ofScore` in `front/src/Band.elm` gives a beach one of five bands, and the
band is a CSS class, never an inline `style=`. Each beach is one DOM marker: a 16 px dot with a
white ring. The picked beach grows to 32 px and shows its score. A water sampling point is a
droplet, so it never looks like a beach. The client writes all markers as one JSON text.
`maplibre_ffi.mjs` builds the DOM nodes from that JSON with `createElement` and `createTextNode`.
A beach name that holds `<` stays text.

The Mapbox `composite` water layer (the thin coastline) does not exist in the new page's style.
The new page does not draw it.

### CSP

`policy` in `back/server/src/Marola/Csp.hs` is the one value of the policy. The server sends it as a
header (with `form-action 'self'` added; see [the hosting page](5-hosting.md)), `scripts/site_build.sh`
writes it to `dist/csp.txt` (`marola-server csp`), and `front/index.html` carries the same text in a
`<meta>` tag without `frame-ancestors`, which a meta tag cannot set. `scripts/front_check.js` checks
that the two agree.

The policy has `'self'` for scripts, styles, fonts and workers, and one third-party host,
`gibs.earthdata.nasa.gov` (the satellite layers), in `img-src` and `connect-src`. The base map needs
none: its style, glyphs and tiles are the site's own files, fetched under `connect-src 'self'`
([ADR 0006](adr/0006-self-hosted-basemap.md)). There is
one frame source, `frame-src https://open.spotify.com`: the playlist player, an iframe the page adds
only after the visitor presses the Spotify button. It also has `object-src 'none'`, `base-uri 'self'` and `frame-ancestors 'none'`. It has no
`unsafe-inline`, no `unsafe-eval`, and no bare `https:` or `*`.

`img-src` has `data:` and `blob:` because MapLibre decodes a raster tile (a satellite layer) through
an image made from a blob. `worker-src` has no `blob:`: MapLibre starts its worker from the same-origin file
`vendor/maplibre/maplibre-gl-worker.mjs`. It uses a blob worker only for a cross-origin worker URL.
The form action of the contact page is not part of this policy.

### The base map

The style is `/map/style.json`, one constant in `front/src/Config.elm` (`styleUrl`).
`scripts/basemap_style.mjs` writes it from `@protomaps/basemaps`' light flavor: recoloured (DESIGN.md,
"The base map"), labels in Portuguese (`name:pt`, then the local name in Latin script, then
`name:en`), a layer of beach names, and no sprite, so it has no POI icon and no road shield. Its
glyphs are Noto Sans in three stacks under `/map/fonts/`, Latin ranges only; a name in another
script is not drawn, so no other range is requested.

Its one source is `pmtiles:///tiles/marola.pmtiles`. `maplibre_ffi.mjs` registers the `pmtiles`
library's protocol with MapLibre, and the library reads the file by byte range from the server
([5-hosting](5-hosting.md#the-base-map)). The file is deep only around each area. The protocol is
set to fail on a tile the file does not hold, because MapLibre then keeps drawing the nearest
ancestor tile it has; an empty tile would draw a hole. The page ignores that one error
(`Tile not found.`). Any other error before the map's `load` (the style, the file's header) fails
the map: the page shows the beach list and the note `map.failed`.

The WebGL flow layer goes below `trails-line`, a layer the page adds itself, and a satellite layer
goes below the style's first symbol layer, so neither names a layer of the base style. The page
keeps the OpenStreetMap credit (ODbL) and Protomaps' in the attribution control.
